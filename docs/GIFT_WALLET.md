# أكواد الهدايا والمحفظة — test

## الاستخدام

- الأدمن: الإعدادات العامة ← أكواد الهدايا (وتوجد وصلة من إعدادات النقاط).
- إنشاء الكود: اسم الهدية، النقاط، عدد المستفيدين، مهلة إدخال الكود، مدة النقاط بعد شحنه، ثم تأكيد.
- طالب واحد: الحد 1. جماعي: عدد محدد، أو 0 بلا حد. كل طالب يستفيد مرة واحدة فقط.
- مهلة الكود تاريخ/ساعة بتوقيت دمشق؛ 0 يعني بلا انتهاء. هذه المهلة مستقلة عن مدة نقاط الهدية، التي تبدأ عند الشحن.
- تفاصيل الكود تعرض العدد، وقائمة أسماء ومعرّفات المستفيدين وتواريخ الشحن بصفحات من 5.
- إيقاف الكود يمنع الشحن الجديد، ولا يلغي هدايا سبق شحنها.
- ملف الطالب ← هدايا الطالب وصلاحيتها: تعديل تاريخ انتهاء هدية أو إلغاء المتبقي منها بعد تأكيد.
- الطالب: «رصيدي وهداياي» أو `/wallet`، ثم «هداياي وصلاحيتها» أو «شحن كود هدية».
- تظهر كل هدية مستقلة: الأصل، المتبقي، وقت الانتهاء، وحالة صالحة/مستهلكة/منتهية/ملغاة.

## سياسة الأرصدة

- المجاني اليومي يبقى في free_points والمدفوع في paid_points.
- رصيد الهدايا محسوب من point_gifts وقت القراءة، ويستبعد المنتهي والملغى. لا يعتمد على مؤقت Redis أو مهمة تنظيف لكي تنتهي الصلاحية.
- نقاط الانضمام الجديدة: هدية بصلاحية 30 يومًا. قيمتها تبقى من welcome_points.
- إعداد welcome_gift_days قابل للتعديل؛ 0 بلا انتهاء. يسري على الهدايا المستقبلية.
- مكافآت الإحالة الجديدة تذهب إلى الهدايا أيضًا. referral_gift_days افتراضيًا 0 للمحافظة على دوام المكافأة السابق؛ ويمكن تغييره.
- لا تُحوّل الأرصدة القديمة المختلطة لعدم وجود دليل كافٍ على مصدرها.
- ترتيب الخصم: مجاني، هدايا أقرب انتهاء أولًا (غير المنتهية في النهاية)، ثم مدفوع.
- الخصم والشحن بقفل صف المستخدم. شحن الكود يقفل صف الكود كذلك، ويحفظ المنحة والاستفادة والعداد في معاملة واحدة.
- سجل wallet_debits يحفظ تقسيم كل خصم وهوية الهدايا المستهلكة. الاسترجاع بنسب تراكمية 0.5 أو 1 لمنع التكرار؛ يرجع النقاط لهديتها الأصلية بصلاحيتها وإلغائها الأصليين.
- جلسات FSM القديمة التي سبقت هذا التحديث تحتفظ بمسار الاسترجاع free/paid القديم.
- جميع الجداول وواجهات RPC الجديدة خاصة بخادم البوت/service_role؛ صلاحيات الجداول والدوال القديمة لم تتغير.

الترحيل إضافي: أربعة جداول وسبع دوال جديدة وإعدادان جديدان. لا يغيّر رصيد أي مستخدم قديم أو تعريف/صلاحية دالة قديمة. قبل التطبيق كان المشروع التجريبي يحوي 3 مستخدمين والإعدادات: ترحيب 150، يومي 25، إحالة 25.

### الاختبارات المحلية

```sh
python -m unittest discover -s tests -p 'test_gift_wallet.py'
python -m unittest discover -s tests -p 'test_*regressions.py'
python -m unittest discover -s tests -p 'test_admin_users_pagination.py'
python -m unittest discover -s tests -p 'test_resource_cleanup.py'
python -m unittest discover -s tests -p 'test_payment_service.py'
npm ci --prefix tests/sql
node tests/sql/gift_wallet_test.mjs
```

129 اختبار Python (10 للهدايا، 20 regressions، 8 صفحات إدارة، 6 تنظيف/تسجيل، 85 دفع)، و13 سيناريو SQL محلي باستخدام PostgreSQL/PGlite. اختبارات SQL تتحقق من قيود التكرار، الحدود، الانتهاء، ترتيب الخصم، استرجاع جزئي وكامل متكرر، عدم إعادة إحياء هدية منتهية، الإلغاء، الإحالة وصلاحيات الوصول والأرصدة القديمة. PGlite اختبار محلي وليس محاكاة شبكة تيليجرام ولا برهانًا لاختبار تنافس بين خوادم PostgreSQL متعددة.

### الرجوع

عند الحاجة ارجع كود البوت إلى نسخة ما قبل التغيير وأبقِ جداول الهدايا والسجلات الجديدة؛ حذفها بعد بدء الاستخدام يضيع أرصدة وسجلًا مهمًا. النسخة القديمة لن تنفق الهدايا لكنها ستظل محفوظة. لا تشغّل rollback يحذف الجداول تلقائيًا، ولا تحوّل الهدايا إلى مدفوع. أعد الإصدار الجديد لاستئناف التعامل مع الهدايا. احتفظ بسجلات wallet_debits ما دامت هناك عمليات قابلة للاسترجاع.
