- `knowledge` رصيد للصرف و`knowledge_earned` مجموع الإنجاز؛ الشراء ينقص الأول فقط. يبدأ نظام الرصيد عند التفعيل، ولا تُحوّل نتائج الجولات القديمة تلقائيًا.
- أول إجابة صحيحة على محتوى السؤال تمنح 100 معرفة مرة واحدة لكل لاعب عبر الاختبارات. `mastery_key` يتجاهل ترتيب الخيارات والتوقيت وروابط الصور والمسافات الزائدة؛ تغيير محتوى السؤال أو إجابته يعطي محتوى مختلفًا. تكرار السؤال يبقى مفيدًا للمراجعة ونتيجة الجولة، دون تكرار مكافأة الرصيد.
- هدف يومي: الإجابة عن 5 أسئلة مختلفة، بتوقيت Asia/Damascus. الإجابة الخاطئة تُحسب مشاركة، وانتهاء الوقت دون إجابة لا يُحسب. لا نقاط إضافية للهدف ولا سلسلة أيام أو عقوبة غياب أو فقدان للمشتريات.
- `runner_commit_answer` يحفظ انتقال الجولة وإيصال الإتقان والهدف ومكافأة المعرفة في transaction واحدة، ويعيد النتيجة نفسها عند التكرار. قواعد الإجابة والفرص و`runner_core.enabled()` محفوظة. /buy-car يستقبل المستوى المقصود صراحة، فتكرار ترقية المستوى 2 لا يشتري المستوى 3.
- Migration `20261020193546_runner_knowledge_car.sql`: توسعة المحفظة، runner_mastery وrunner_daily_study مع RLS ومنع الوصول العام، دوال SECURITY INVOKER/search_path فارغ وصلاحية service_role فقط. سجلات الإتقان تبقى عند حذف اختبار حتى لا تعود المكافأة لنفس المحتوى. SQL واختبارات المعاملات تتحقق من rollback وعدم تكرار الصرف والخصم.
- تصحيح بصري: بنطال رملي فاتح لتمييز اللاعب عن الطريق، والعملات ترتفع بمنظور المسافة أثناء الطيران، والحواجز تبقى أرضية. مؤثر الالتقاط يبدأ من موضع العملة المرتفع.

## الرصيد والعملات

- العملات رصيد خاص باللاعب عبر كل اختبارات Runner؛ منفصل تمامًا عن نقاط المعرفة ورصيد البوت المالي. يبدأ من صفر لأن العملات السابقة كانت مؤقتة في المتصفح.
- حقيبة الطيران النفاثة: **100 عملة، شراء دائم وطيران بلا حد**. تبدأ مفعلة في الجولات التالية، وزر طيران/هبوط يبدّلها. تتجاوز العوائق وتسمح بجمع العملات في المسار الحالي؛ لا تتجاوز الأسئلة أو أخطاء الإجابة.
- الصفحة الرئيسية والمتجر وHUD يعرضون الرصيد. الملكية والرصيد محفوظان على الخادم. لا تعتمد الملكية على localStorage.
- `20261020191247_runner_wallet.sql`: جداول `runner_wallets` و`runner_tracks`، RLS ورفض anon/authenticated، ثلاث دوال SECURITY INVOKER مع search_path فارغ وصلاحية service_role حصراً.
- الشراء transaction تقفل المحفظة: الخصم مرة واحدة، تكرار الطلب يعيد الملكية، ولا رصيد سالب. العملات تُضاف مع إيصال المسار في transaction واحدة.
- `/track` يصدر عشرة عناصر محددة بالمعرف والنوع والمسار والتوقيت لكل سؤال، ويعيد نفس المسار عند إعادة الطلب. `/coins` يستقبل معرفات فقط، ويتحقق في DB من المالك والصلاحية ووقت الوصول والنوع ومنع التكرار. لا يقبل مبلغاً أو رصيداً من العميل.
- المحاكاة والتحكم بالمسار على العميل: هذه حماية محدودة للاقتصاد الترفيهي، وليست إعادة محاكاة كاملة لمكافحة الغش؛ عميل معدل يمكنه طلب العملات الصحيحة بعد وقتها دون إثبات الحركة. لا تحويل إلى مال أو نقاط البوت.
- الحفظ أثناء الركض، وعند الخلفية، وإرسال keepalive عند الإغلاق. تُحفظ معرفات الإيصالات المعلقة محلياً لكل حساب Telegram لإعادة المزامنة، دون حفظ initData. الإيصالات غير المؤكدة تحتاج عودة الشبكة قبل انتهاء الجولة (ساعتان) وتظهر «جارٍ حفظ العملات»؛ إغلاق الجهاز بلا اتصال ثم حذف تخزينه لا يمكن ضمانه.
- حذف الاختبار أو تنظيف الجولات يحذف المسارات فقط؛ رصيد اللاعب وملكية الحقيبة باقيان. حذف حساب المستخدم يتبع FK المعتاد.

التحقق: Python API/identity regression، SQL PGlite للسعر والرصيد الناقص والتكرار وتوقيت العملات والعزل وRLS، UI logic، Chrome بحجم الهاتف للشراء المزدوج وإعادة الفتح والطيران عبر عائقين مع استمرار الأسئلة واستعادة إيصال بعد انقطاع الشبكة.
