# Backup — المرحلة الثانية

بتاريخ 2026-10-04، لم تؤخذ نسخة احتياطية جديدة من Supabase، ولم تُطبّق 0008 أو 0009 على أي مشروع سحابي.

الوصول إلى Supabase متاح في هذه الجلسة. فحص read-only للمشروع المسمى `telegramquizbot` أعاد NULL لكل من `public.challenge_tests` و`public.challenge_matches`: جداول المرحلتين غير موجودة فيه وقت الفحص. لم نستخدم مشروع `Test_telegramquizbot` ولم نغيّر أي مشروع.

الأدوات المتاحة تدعم SQL والفروع، لكنها لا توفر عملية تصدير/Backup قابلة للاسترجاع أو بيانات اتصال خاصة لـ pg_dump. إنشاء فرع بلا بيانات ليس Backup. ملف ZIP المرفق نسخة للكود فقط، وليس قاعدة البيانات.

## قبل النشر

1. خذ Backup حديثًا من اتصال قاعدة البيانات لديك أو من خدمة Backups في Supabase. لا ترسل كلمة المرور ضمن المحادثة أو Git.
2. باستعمال `pg_dump` بإصدار مناسب للخادم (17 أو أحدث متوافق):

```bash
pg_dump "$DATABASE_URL" --format=custom --no-owner --file=abiad_before_challenges.dump
pg_restore --list abiad_before_challenges.dump
```

3. أنشئ قاعدة اختبار منفصلة فارغة ومهيأة بأدوار Supabase اللازمة. استرجع فيها النسخة (لا تنفذ الاسترجاع على الإنتاج):

```bash
pg_restore --exit-on-error --no-owner --dbname="$RESTORE_TEST_DATABASE_URL" abiad_before_challenges.dump
```

4. تحقق من نجاح الاسترجاع ومن أعداد الجداول الأساسية والمحتوى والقيود والدوال والسياسات. تحقق من بيانات `challenge_*` إن كانت موجودة عند أخذ النسخة. سجل التوقيت، checksum، المكان، ونطاق النسخ ونتيجة الاسترجاع. قد تتطلب قاعدة Supabase المستهدفة مسار الاسترجاع الرسمي الخاص بها لتجنب التعارض مع schemas التي تديرها المنصة.
5. نسخة قاعدة البيانات لا تنسخ ملفات R2/Storage نفسها؛ انسخها منفصلًا إن كانت خطة التعافي تشمل الملفات.
6. طبّق `0008_challenge_content.sql` ثم `0009_challenge_game.sql` على **بيئة الاختبار** واختبر البوت بحسابين قبل الإنتاج. لا تشغّل ملفات `_rollback.sql` ضمن ترتيب التطبيق.

لا يوجد توقيت أو مكان أو checksum لنسخة قاعدة بيانات من هذه الجلسة، لأن نسخة لم تُؤخذ. لا تعتبر هذه الوثيقة إثبات Backup.
